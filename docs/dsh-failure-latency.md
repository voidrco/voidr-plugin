# Monitor failure evidence and latency

Monitor starts with the failure-analysis tool profile and the complete failure-analysis skill. Other capabilities remain available through the existing per-turn scope expansion. Service authorization, runtime guards and confirmation rules remain authoritative. Authoring, execution and deployment instructions load through their original skills when the user changes tasks.

For an exact execution and case, `failure_analysis_read_bundle` validates execution identity, reads complete failure pagination and gathers eleven source types through `ctx.tools.execute`. It preserves the agent, parent call, root call and cancellation signal. Application and history scope are checked. At most three reads run concurrently, with a 60-second overall deadline. Offloaded sources use bounded hydration through the same authorized artifact tool. No source mutation, model request, job, test run or alternative credential is involved.

The compact view preserves every selected failure record, separate message and stack fields, exact sample counts, source hashes, all failed/timed-out trace steps, bounded context, history aggregates and explicit omissions. ANSI formatting is removed only for classifying error fields. Raw field prefixes remain separate. Unavailable sources are gaps, not empty results; sampled or omitted data cannot establish absence.

Selected Monitor sessions expose the initial collector first, then bounded detail reads and the report tool. Presentation filtering does not remove the composite's authorized child tools. Model-direct full dumps and generic dispatchers require explicit scope expansion; parent dispatch still traverses the original authorization and approval checks. A maximum of three attempted detail reads follows the initial pass. Excerpts support exact field paths, literal filters, source row positions, pagination, size bounds and detection of changes since collection. New turns, user steering and context changes invalidate the read window.

`failure_analysis_render_report` optionally publishes an initial source-bound panel using the existing Platform Markdown widget. It leaves the turn open for the final answer and bounded investigation. The model selects only unconfirmed hypothesis kinds and proposed checks for the panel. Counts, every selected row, UTC times, durations, independent error classes, references and uncertainty come from the collected source data. Model-authored panel prose, classifications, rows and evidence references are rejected. A snapshot, console error, HTTP status or later pass cannot establish or exclude a cause through this tool. Proposed checks are not executed. Necessary detail reads and explicit expansion remain available after publication, while duplicate panels are excluded from the active catalog.

## Qualification and limits

This is a review candidate without production latency or connection qualification. It deliberately distinguishes an initial evidence report from a completed causal investigation. A short initial report cannot substitute for the latter or pass a production p95 gate by changing the task's depth.

It used the investigator's own authorized organization account for live read-only Service calls and an organization-scoped inference key. It did not reproduce Milson's authenticated browser/session path. Native sessions used the actual production DSH image `sha256:daf1798838ffafdb547d9639935f680bdf72df2d46aa2af8acd12046707b3b55`, fresh workspaces, the same DeepSeek model and high reasoning unless an explicitly named exploratory effort trial says otherwise. Provider metadata independently confirmed all 13 generations across the three initially pinned Relace trials. The subsequent actual-wrapper trial separately verified primary versus auxiliary routing.

The corrected report preserves all four selected records and the 120,000 ms message versus 10,000 ms stack discrepancy. It distinguishes nine failure records from four distinct cases, and 114 occurrences of one console message from the other twelve messages in the sample. The actual Platform `WidgetRenderer` rendered these facts correctly in a local browser fixture through Playwright MCP, with no rendering alert. This was not an authenticated product/browser latency measurement.

The corrected Relace replay observed 7.399 seconds of native-process CPU, 293.705 ms of GC and a maximum individual GC of 12.523 ms; the p95 of one-second maximum event-loop delays was 42.107 ms. Startup produced a 1.325-second maximum stall. These component measurements do not establish whole-node CPU reserve, an AMD full-Hive result or a production p95.

Earlier OpenInference trials exceeded the six-minute safety deadline and included interrupted streams and further model planning. A non-streaming replay of an identical post-collection request took 114.20 seconds and still requested more reads. An exact-body transport probe reset on the public route after 22.10 seconds while receiving data, whereas the direct serving revision completed its separate generation in 142.33 seconds. Those observations do not isolate the cause to Cloudflare, the gateway or the provider. Connection remediation remains unqualified; routing and reasoning changes were confined to the fixture. An independent Hive change adds a disabled-by-default `DSH_MONITOR_LLM_PROVIDER=relace` opt-in for the measured route, preserving the model, high reasoning and existing caller restrictions. It does not enable a deployment or update the plugin pin.

Unsuccessful trials remain in the private evidence, including rejected semantic answers, unsupported `medium` effort, an invalid fixture tool scope, excerpt-path handling and an early report-reference API that caused a bounded retry loop. They are not excluded to claim success. The final report API derives rows and references itself rather than asking the model to copy them.

The production runtime inspected pins plugin `db789f703ac457670d52579d05fdcca64856a25c`, which has no surface tool profiles. Merging plugin code alone does not activate these changes: a separately reviewed Hive plugin pin/release and authenticated product validation are still required. Private requests, model reasoning, raw organization evidence and credentials are not committed to this repository.

No production routing, capacity, budget, IAM or canary is changed. The DSH component fixture used an existing provisioned node, not an added node or node pool. Hive #630 remains draft; its separate gate requires real-traffic p95 no more than 20% above baseline and at least 15% whole-node CPU headroom.

## Full-answer study following the Serasa report

Milson requested a baseline and a coordinated improvement to the harness experience in the Serasa failure analysis on 22 October. Completion means a useful final answer to the same question and case, with source-specific counts, UTC times, independent error fields and supported conclusions. A preliminary panel, first token or proposal for later investigation is not completion. The earlier 20.093-second panel is component evidence only; it cannot qualify this final-answer criterion.

The original completed production turn took 2074.859 seconds across 25 rounds and 26 tools. Joined gateway records account for 1920.367 seconds; 34850 of 39353 output tokens were reasoning. The catalog held 411 tools and 413079 schema characters. Static headers were stable, so static-header churn has not been established as the cache cause. The two observed DSH event-loop stalls cannot explain the full delay. Backend and prompt-cache associations remain observational.

A later normal-browser authenticated control explicitly pinned the historical execution in the user message because the current Monitor context selected a newer execution. Native reads confirmed the requested original scope. It was stopped administratively at 659.374 seconds without a completed answer, after 20 tools and 13 steps. Twelve provider streams completed; the thirteenth closed after cancellation. This is censored latency, not a completed baseline or provider failure. A 35-second browser timeout matched a 36.109-second Service OPTIONS preflight. Its cause is unresolved. The partial N2 node sample had 60.89% headroom at p95 of five-second CPU means and a 99.50% one-second usage peak; it does not qualify AMD or production p95.

The revised candidate keeps the initial panel optional and nonterminal. It retains bounded evidence collection, detail reads and explicit expansion for essential missing sources, then requires an answer about the observed failing operation and the strongest supported explanation. It must not confirm causality from a snapshot, later pass, HTTP status or console count alone. It must not exclude unresolved alternatives.

The next component comparison holds the effective model, high reasoning, output budget, backend, question and selected execution/case constant. Record terminal turn state and the final assistant answer separately from progress and widgets. Report every timeout, transport failure, incomplete source and rejected answer. Audit all selected records and their own timestamps/timeouts, the message/stack discrepancy, sample counts and causal limits. Model steps, source reads, request size, connection timings, CPU, GC and event-loop delay are supporting metrics. Keep synthetic/component results separate from the authenticated product and real-traffic p95. No capacity increase or #630 activation is part of this study.

The independent history-transport change aims to reuse preflight cache entries across cursor changes with a stable URL, retaining authorization, pagination and old-client/server compatibility. The [Fetch standard](https://fetch.spec.whatwg.org/#cors-preflight-cache) keys those entries by URL, origin and related request attributes; raising max-age alone cannot reuse an entry for a different cursor URL. This addresses avoidable transport work, not the dominant model-generation time.


### Completed-answer comparison and processing attribution (22 October)

The matched v2 component pair used the genuine SDK skill loader, production plugin `db789f703ac457670d52579d05fdcca64856a25c` for A, candidate `70978776caa007ba555e6d377f46db8a3ba14f80` for B, the actual compiled Hive wrapper `ba769050a1df2db45a6dfb1bc4f0c6d7d3203e17`, Relace, the same model, high reasoning and 256000 output budget. The baseline completed in 145.382 seconds over nine requests, but omitted the required per-record timestamp associations. The candidate completed in 165.347 seconds over five requests, including the auxiliary title request. It preserved the source records but still made unsupported exclusions from DOM snapshots. Neither answer passes the combined factual and semantic criterion; this pair does not establish a useful-answer speedup. Earlier B1 took 60.159 seconds and was also rejected semantically; its mock skill loader differs from v2 and it is not a matched control.

For candidate B2, the four primary model calls totalled 162.024 seconds of the 165.347-second interval. They produced 15959 reasoning tokens. One call spent 104.317 seconds streaming, with first reasoning at 1.086 seconds and first text at 99.665 seconds. The native process accumulated 13.211 CPU seconds across 167 one-second samples, with 418.410 ms of GC. The p95 of the per-sample event-loop p95 was 21.430 ms; maximum observed delay, including startup, was 1498.415 ms. CPU time overlaps network/model waiting and is not an additive wall-time partition. The samples show that local DSH CPU/GC does not explain the dominant delay in this isolated run; they do not rule out local contention during production bursts or establish whole-node headroom.

The fixture used an already provisioned N2-standard-4 node with a two-CPU/two-GiB pod limit. It is not an AMD qualification or a production capacity experiment. Read-only calls used the investigator's own organization account; live source history can change between sequential trials. Captured evidence, source responses and model bodies remain private. The unsupported medium-effort probe was rejected by `session.selectModel` before any model request. It is not a latency measurement and no production reasoning setting was changed.
